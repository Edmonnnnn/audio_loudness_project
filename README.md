🎧 Audio Loudness Normalizer & Tag Editor
Audio Loudness Normalizer & Tag Editor — это современный онлайн‑сервис для анализа, нормализации и пакетного редактирования аудиофайлов (MP3, WAV, FLAC), включая расширенную работу с тегами (ID3) и обложкой. Всё работает локально — ваши файлы и история не уходят во внешний интернет.

📦 Основные возможности
Нормализация аудио по LUFS и Peak
Поддержка MP3, WAV, FLAC. Настраиваемый Target LUFS, экспорт в выбранный формат, установка битрейта и пресетов.

Визуализация графика громкости
Автоматическая генерация графика изменения LUFS во времени для каждого трека.

PDF‑отчёт
Подробный отчёт по результатам обработки: исходные и итоговые параметры, график, все теги (включая расширенные поля), обложка.

История обработок
Вся история обработанных файлов доступна во вкладке History (сортировка, просмотр, обновление).

Редактор тегов MP3
Веб-UI для чтения, изменения и записи тегов (title, artist, album, date, genre, composer, discnumber, comment, albumartist, publisher, website, tracknumber), а также загрузка и встраивание обложки (JPEG/PNG).

Мгновенная нормализация редактируемого MP3
После изменения тегов можно сразу же нормализовать этот файл без повторной загрузки.

Тёмная/светлая тема интерфейса
Современный дизайн, доступность на мобильных устройствах.

Безопасность
Все временные файлы, история и пользовательские данные НЕ попадают в облако или интернет.

    🧪 Подробная инструкция для тестировщика (QA)
Общие принципы
Тестирование проводится на локальной машине (Windows, macOS, Linux) после запуска через python run_all.py.

Для каждого этапа тестирования делай отдельные прогоны для разных файлов: MP3 (c ID3v2), WAV, FLAC.

Особое внимание:

Проверь работу с файлами, в которых уже есть сложные/нестандартные теги.

Используй не менее 2–3 MP3 с разной структурой тегов и разными обложками (размер, формат).

Все действия документируй: какой файл, какие шаги, какие результаты.

1. Проверка нормализации (Normalize)
Стандартная обработка

Перейти на вкладку Normalize.

Загрузить валидный MP3, затем WAV и FLAC.

Ввести Target LUFS (например, -14).

Выбрать формат экспорта (mp3, wav, flac), задать bitrate, preset.

Нажать "Normalize".

Ожидать скачивания ZIP-архива.

Проверить содержимое архива:

Есть нормализованный аудиофайл выбранного формата.

Есть report.pdf.

Есть loudness_plot.png (если был построен).

Открыть report.pdf:

Проверить: указано имя файла, LUFS до и после, Peak, Target LUFS, дата генерации.

Проверить наличие графика.

Проверить раздел "Tags" (см. далее).

Открыть итоговый аудиофайл любым плеером.

Он должен проигрываться без ошибок.

По длительности совпадать с исходником.

Работа с невалидным файлом

Загрузить повреждённый/битый MP3 или файл другого формата.

Ожидать сообщение об ошибке (от сервера или UI).

2. Проверка редактора тегов (Tags)
Стандартная работа с тегами

Перейти на вкладку Tags.

Загрузить валидный MP3 с заполненными тегами.

Проверить, что все поля UI заполнены (Title, Artist, Album, Date, Genre, Composer, Disc Number, Comment, Album Artist, Publisher, Website, Track Number).

Изменить 3–4 любых поля, добавить/заменить обложку (jpg/png).

Нажать "Save Tags".

Дождаться статуса "Tags saved!".

Не покидая вкладки Tags, нажать "Normalize This MP3".

Скачать ZIP, открыть report.pdf, убедиться, что все изменённые теги и новая обложка отображаются в PDF!

Открыть обновлённый MP3 из temp_files сторонним тег-редактором (Mp3tag, VLC): убедиться, что теги действительно обновились на файловой системе.

Граничные случаи

Удалить обязательные поля (Title, Artist), нажать "Save Tags" — убедиться, что система не позволяет сохранить пустые обязательные поля (или возвращает ошибку).

Попробовать загрузить не-MP3 — система должна вернуть ошибку.

Загрузить некорректную обложку (например, gif) — убедиться, что появится предупреждение.

3. Проверка мгновенной нормализации редактируемого файла
Сценарий "Редактирование → Нормализация"

После успешного сохранения тегов, не перезагружая страницу, нажать "Normalize This MP3".

В появившихся окнах задать параметры (LUFS, формат и т.д.).

Дождаться архива, открыть PDF — все изменённые теги должны отображаться.

Сравнить отчёт и аудиофайл до и после изменений тегов.

Ошибка: отсутствует файл

Удалить файл из temp_files вручную, попытаться нажать "Normalize This MP3" — ожидать ошибку "File not found after tag edit!".

4. Проверка истории обработок (History)
Работа с историей

Перейти на вкладку History.

Нажать "Refresh" — должна появиться таблица.

Проверить сортировку по дате (последний обработанный — сверху).

Кликнуть по ссылкам графика (View) — открывается изображение.

Убедиться, что информация о всех обработках корректна и совпадает с архивами.

Массовая обработка

Провести несколько последовательных нормализаций с разными файлами.

Проверить, что история обновляется после каждой новой обработки.

5. Проверка UI/UX и безопасности
Навигация

Переключение между вкладками — без багов, без сброса данных.

Внешний вид в светлой и тёмной теме.

Все элементы UI реагируют на ошибки корректно.

Файлы и безопасность

Проверить, что все временные файлы (mp3, pdf, plot.png) хранятся только в temp_files и не выгружаются в сеть.

После закрытия/перезапуска приложения старые временные файлы можно удалить вручную (или они удаляются автоматически при очистке).

6. Проверка на баги/граничные случаи
Загрузка файлов с длинными именами, спецсимволами, кириллицей.

Проверка работы на разных браузерах (Chrome, Firefox, Edge).

Открытие и повторная обработка одного и того же файла.

Одновременное открытие нескольких вкладок (не должно быть конфликтов).

Ручная очистка temp_files и повторное тестирование обработки.

7. Проверка логов
В терминале должны отсутствовать необработанные исключения (traceback, error).

Серверные сообщения об ошибках должны быть информативны.

8. Оформление отчёта
В отчёте по тестированию обязательно фиксируй:

Версию проекта (коммит/дата).

Какие файлы тестировались (имя, длительность, изначальные теги).

Какие баги или нестыковки обнаружены (если есть — с логами и скриншотами).

Что протестировано полностью и подтверждено ✅.
